## Comparison design

- Population: all 100 existing authored knowledge tasks, original dev/test split retained. These tasks have been seen in earlier evaluation; this is a post-exposure diagnostic rerun, not a newly hidden test or predictive holdout.
- Baseline software proxy: title-keyword retrieval plus the same conservative template, evidence validator, lead eligibility and safety checks. FIFO is the operational queue reference, reported separately. No measured manual sales effort is available; this baseline must never be described as observed human work.
- Assisted software proxy: actual four-read bounded workflow with lexical retrieval, identical template/validation and offline planner. No live LLM. This measures orchestration/retrieval behavior, not model reasoning or causal business impact.
- Design: two serial repetitions of every task in each arm, alternating/randomized seeded arm order, four paired warm-up tasks recorded separately. Record every attempt/output/state, document/fixture/code/config hashes, elapsed monotonic time, workflow/run IDs, actual provider-attempt counts and any failures. Persist raw JSONL. No tuning after observing results.
- Quality: count exact gold-document relevance, justified abstention, false abstention, unsupported/irrelevant completed responses and technical failures separately. A failure is not a successful abstention. Preserve task-level paired outcomes; repeated runs do not increase the independent sample. Surface grounded-but-irrelevant answers, not just citation validity.
- Uncertainty: report original split/family counts; paired family-cluster bootstrap intervals (seed fixed, 2,000 resamples) as descriptive uncertainty conditional on this authored fixture. Report all-case useful-task rate and answerable/abstention denominators; tiny category/family groups remain uncertain. Latency includes software only, with warm-up and local environment caveats. No human-time savings are inferred from API milliseconds.
- Cost: default templates must create zero provider attempts; actual invoices/hosting/labor remain null, not zero. Existing scripted costs are simulated and stay separate. All technical failures/retries count in attempted-run denominators.
- Evidence ledger: synthetic observed computation, unavailable real retrospective analysis, unavailable prospective pilot, assumptions, and simulations are distinct categories. Never transform synthetic outcome counts into predictive accuracy, real time saved, realized ROI or client results.
- Deliverables: reproducible technical report, architecture diagram, evidence-based business case plus labeled scenario calculator, honest engineering case study, GitHub README, and a timed interview demo/runbook with failure path and known limits.

Acceptance: fixture assertions and full regressions pass; raw attempts reconcile to expected task/arm/repetition counts; at least one adversarial and insufficient-evidence case is visible; bootstrap is deterministic and paired; evidence/cost categories are enforced by tests. Report every quality gate, including failures. No numerical quality improvement is required to call the experiment executed. An unfavorable result is valid evidence.
