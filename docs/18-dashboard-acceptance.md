# Dashboard acceptance criteria

Repository inspection on 2026-10-16 found the existing 145-test Python/PostgreSQL application, migrations 0001–0005, no API/frontend, and an unexecuted hosted CI configuration. Preserve these services. Owner selected Google Workspace as hosted identity provider. No live model or delivery connector is authorized.

1. Add a FastAPI modular monolith serving a React/TypeScript dashboard from the same origin. Display synthetic/freshness/interval markers, pipeline by currency, qualification and win-rate denominators, explained lead priority, cited recommendations, exact-version approval queue, evaluation evidence and business KPI limitations.
2. Authentication must derive organization/actor from server identity mappings, never browser arguments. Local password login is loopback/synthetic only; Google OIDC uses maintained Authlib, state/nonce/PKCE validation and explicit Workspace hd/verified-email/subject allowlists. Use opaque revocable database sessions, HttpOnly/SameSite cookies, CSRF and origin checks, expiry and login throttling. Do not claim live Google authentication until credentials and redirect setup are tested.
3. Readers can inspect their own validated recommendations and generate bounded offline templates. Explicit assigned reviewers can inspect and decide exact action versions. Browser cannot assign reviewers or send messages. Revalidate all existing approval constraints. Stale decisions are visible errors, never automatic retries.
4. Provide loading, empty, expired-session, forbidden, stale-data, and service-error states; keyboard-accessible forms/tables/navigation; responsive layout, no invented charts/ROI. Existing failed evaluation gates remain visible.
5. Monitoring: readiness/liveness, redacted structured request IDs/status/timing logs, authenticated operational counters and a documented alert/backup/incident runbook. Add deployment container, same-origin config, dependency locks and CI for Python, frontend build and real browser/API/PostgreSQL tests.
6. Test authentication, membership revocation, cross-scope input rejection, CSRF, session expiry/logout, error redaction, exact approval conflicts and DB outage. Run a real Chromium flow against the actual API and PostgreSQL, not mocked dashboard data. Report actual results separately from untested Google/cloud/container/load behavior.

Dependencies: existing SQLAlchemy/Alembic/Pydantic; new FastAPI/Uvicorn, HTTPX, Authlib/itsdangerous; React/ReactDOM/TypeScript/Vite; Playwright and accessibility checks for browser verification. No charting framework, UI component suite, agent framework or additional hosted service is needed. Detailed design, simpler alternatives and measured results follow in docs/19-dashboard-guide.md and docs/20-dashboard-verification.md.
